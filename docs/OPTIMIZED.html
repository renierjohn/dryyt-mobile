UI performance

Changes that make the app scroll and animate more smoothly and use less CPU, memory and battery, without changing what any screen does.

Overview

The app is Expo SDK 57 / React Native 0.86 on the New Architecture. Most of the remaining cost comes from four places: lists rendered all at once, GPS running at full accuracy, timers that re-render whole screens, and polling that duplicates the WebSocket.

Plan

1. Virtualized lists

All 31 screens render through Screen (src/components/screen.tsx), which wraps children in a plain ScrollView, so every row of a long list was mounted at once, including rows off screen.

Done
  • Screen takes virtualized: each child becomes one row of a FlatList (no new dependency). Children.toArray drops null rows, so stickyHeaderIndices, pull-to-refresh, header, footer and safe area work as before.
  • initialNumToRender={20}: day titles and separator lines are rows too, so the default 10 could leave a tall screen half empty.
  • Used by the paged, day-grouped lists: history-list.tsx (customer and driver history), owner-orders.tsx (Orders and Pickups tabs), owner/(tabs)/index.tsx (Drop offs).
  • owner-orders: PhotoViewer moved outside the list, so scrolling its row out of the window can't close an open photo.
  • Short forms and detail screens stay on ScrollView; text inputs in a virtualized list can unmount when scrolled away.
<Screen onRefresh={orders.refresh} virtualized stickyHeaderIndices={…}> {top} {rows} {showMoreButton} </Screen>

2. GPS battery

Done
  • useWatchLocation (driver location every 10 s) uses Accuracy.High instead of BestForNavigation; a fix every 10 s doesn't need the extra sensor fusion.
Kept
  • distanceInterval: 0: the worker drops a driver after 30 s without a fix, so a distance filter would drop drivers standing still.
  • useCurrentLocation keeps BestForNavigation to refine the customer's pin, but it already stops at 10 m accuracy or after 20 s.
  • The watcher already runs only while enabled (online / on a trip).

4. Polling vs socket

Already in place
  • usePoll in src/hooks/queries.ts polls only while the screen is focused.
  • While a socket is live (isLive()), each polled query slows to LIVE_POLL_MS (30 s). That poll is kept as a safety net for missed socket messages.
  • The pickups socket already writes the jobs list with setQueryData.

5. Background screens

Screens that are still mounted but hidden (screens lower in the stack) kept re-rendering when polls or socket messages arrived.

Done
  • freezeOnBlur: true on the owner and customer stacks (src/app/owner/_layout.tsx, src/app/customer/_layout.tsx). A frozen screen keeps its state, sockets and effects; it just doesn't re-render until it's shown again.
Not frozen
  • Driver tabs and the root stack: the driver's new-job sound (useNewJobSound) fires from render, so freezing the Available tab could silence it while the driver is on another tab.

6. Images

Done
  • cachePolicy="memory-disk" on images that repeat in lists: DishPhoto, StoreLogo, dish photos in customer/new-order.tsx, store photos in customer/stores.tsx. Scrolling back shows them from memory instead of decoding from disk again.
Already in place / not needed
  • Uploads already go through shrinkImage (src/lib/shrink-image.ts): 1600 px, under 1 MB.
  • expo-image already downscales to the view size when decoding.
  • recyclingKey: only matters for recycling lists (FlashList); FlatList doesn't recycle rows.
  • Payment photos (sent with auth headers) keep the default disk cache.

7. Animations

Done
  • src/components/sortable-list.tsx (menu reorder): rows moved by animating top, which re-runs layout every frame of a drag. They now move with transform: translateY.
Already in place
  • All animations use Reanimated on the UI thread; nothing uses React Native Animated.
  • The payouts tab slide and photo viewer already animate transforms only.
Rule for new code
  • Animate transform and opacity, not width, height, top or margin.

8. Release builds

Done
  • Android: enableMinifyInReleaseBuilds and enableShrinkResourcesInReleaseBuilds in the expo-build-properties plugin (app.config.js). This is a native change, so it needs a new build (it doesn't ship through EAS Update).

R8 can strip classes that a library loads by reflection. Before shipping, build a release APK and check sign-in (Google, Facebook, phone), push notifications, the face camera and image upload. If something crashes, add a keep rule or turn the two flags off.

Skipped
  • babel-plugin-transform-remove-console: the app has only two console calls (a crash log and a __DEV__-only warning), so it isn't worth a new dependency.

Measuring

Dev builds are much slower than release builds. Measure on a release or preview build on a low-end Android phone.

1. Build: bun run gradle:preview 2. FPS: Dev menu → Perf Monitor (UI and JS frame rates) 3. Renders: React DevTools → Profiler → "Highlight updates when components render" 4. Startup: EAS Observe (cold launch, TTI) 5. Battery: Android Settings → Battery → App usage, after a 30 min driver shift

Record each number before and after each change.

Render debugging

React Native DevTools ships with the dev build. Keep Metro running (bun run start) and the app open on the phone.

1. Open DevTools

Metro terminal → press j or Shake the phone → "Open DevTools"

It opens in Chrome or Edge on the Mac.

2. Highlight re-renders

⚛︎ Components tab → ⚙︎ settings → General → "Highlight updates when components render"

Each component that re-renders flashes an outline on the phone. The color goes from blue (rare) to red (frequent).

3. Profiler: why and how long

⚛︎ Profiler tab → ⚙︎ → "Record why each component rendered while profiling" ● Record → do the action (scroll a list, open a payout week) → ■ Stop
ViewShows
FlamegraphBar width is render time; grey means it didn't render. Click a bar for "Why did this render?" (props changed, state changed, parent rendered, hook changed).
RankedThe slowest components first.

5. React Compiler check

In the Components tab, components the compiler optimized show a "Memo ✨" badge. A component without it re-renders whenever its parent does, so check for it when one keeps flashing.
