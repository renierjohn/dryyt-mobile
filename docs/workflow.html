Dryyt delivery workflow

How a customer's request becomes a driver's job and moves to delivery. Mobile app (Expo) ↔ Cloudflare Worker (Hono + D1).

Order types

Every order has one store. The type decides which direction the driver travels.

pickupfood

Food pickup

Restaurant → Customer
Customer picks menu items. Server computes prices from the menu; client prices are ignored.
pickuplaundry

Laundry pickup

Laundry shop → Customer
Finished laundry brought home. No items; notes carry the claim ticket. Laundry bill is settled with the shop.
dropofflaundry only

Laundry drop off

Customer → Laundry shop
Driver collects laundry at the customer's address and drops it at the chosen shop.

Customer pays cash to the driver: items total + ₱50 delivery fee.

Order status lifecycle

Each transition is a single conditional UPDATE … WHERE status = ?, so races resolve to one winner (the loser gets 409).

open on job board driver's active job (max 1 per driver, DB-enforced) in driver history terminal

End-to-end sequence

Both apps poll every 5 s, so updates appear without push notifications.
