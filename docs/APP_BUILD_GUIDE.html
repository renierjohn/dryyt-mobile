App builds

How to build the Android app and deploy the worker for preview and production, which API each build talks to, and which signing keys Facebook and Firebase must know about.

Overview

The app reads one setting at build time, EXPO_PUBLIC_API_URL, and calls that worker for everything (REST, WebSockets, images). Preview and production are two separate workers with their own data, so a preview build never touches production orders, users or files.

Preview app ──► app-preview.dryyt.com ──► dryyt-worker-preview ──► D1 dryyt-mobile-preview · R2 dryyt-mobile-preview · own Durable Objects Production ──► dryyt.com ──► dryyt-worker ──► D1 dryyt-mobile · R2 dryyt-mobile · own Durable Objects

Secrets

Secrets belong to one worker and are never copied between them. Set each one with --env preview for preview. Each secret put takes effect at once.

SecretNeeded forPreview
JWT_SECRETSigning sign-in tokens. Different per worker, so sessions don't carry over.set
ORS_API_KEYRoute fallback when OSRM fails.optional
EXPO_ACCESS_TOKENPush sending and receipts; required only when Enhanced Security for Push is on in the Expo project. The same token works for both workers.optional
TURNSTILE_SECRETCpanel sign-in bot check.for cpanel
bunx wrangler secret put ORS_API_KEY --env preview bunx wrangler secret put EXPO_ACCESS_TOKEN --env preview bunx wrangler secret put TURNSTILE_SECRET --env preview bunx wrangler secret list --env preview

CommandTarget

Apply a new migration to preview first, test, then production. The preview database starts empty: create users, shops and an admin there with the scripts in worker/scripts.

App builds with EAS

EAS takes the API URL from the profile in eas.json. A value set there beats every .env file uploaded with the build.

App builds with Android Studio / Gradle

Android Studio and ./gradlew ignore eas.json. The JavaScript bundle gets its values from the shell and the .env files, and the native project from the last expo prebuild.

Which .env files load

Build typeModeFiles, highest priority first
debugdevelopment (JS from Metro).env.development.local → .env.local → .env.development → .env
releaseproduction.env.production.local → .env.local → .env.production → .env

A variable already set in the shell beats every file. There is no "preview" mode: a .env.preview file is never loaded, and a plain release build reads .env.production and calls production.

FileHolds
.envLocal API URL (your LAN IP, port 9999), Firebase SMS key, Google web client id, Facebook app id and client token.
.env.productionEXPO_PUBLIC_API_URL=https://dryyt.com for release builds.
.env.production.localOptional local override (git-ignored). Delete it before building production.

The Facebook app id and client token go into the native android/ project during bunx expo prebuild (app.config.js), not during the Gradle build. After changing them in .env, run prebuild again before building.

Build scripts

Run from the app root, on macOS, Linux or Windows. Each goes through scripts/gradle.ts, which sets EXPO_PUBLIC_API_URL for Gradle (so it doesn't depend on the .env files) and runs ./gradlew, or gradlew.bat on Windows.

CommandAPIOutput
bun run gradle:devMetro (.env)android/app/build/outputs/apk/debug/app-debug.apk
bun run gradle:previewhttps://app-preview.dryyt.comandroid/app/build/outputs/apk/release/app-release.apk (sideload)
bun run gradle:releasehttps://dryyt.comandroid/app/build/outputs/bundle/release/app-release.aab (Play)

Building from the Android Studio Build menu instead: run the same variant with EXPO_PUBLIC_API_URL exported in the shell that launched Android Studio, or use .env.production.local.

Signing keys and fingerprints

Each kind of build is signed with a different key. Facebook Login and Google sign-in work only for builds whose key is registered, so register every key you ship with.

BuildSigned byWhere to get the SHA-1
Local debugandroid/app/debug.keystore5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25
EAS buildsEAS-managed upload keystorebunx eas credentials → Android → com.dryyt.mobile
Local release (Gradle)The keystore in android/app/build.gradle's release signing configkeytool -list -v -keystore <file>
Installed from Google PlayGoogle's app signing key (re-signs your upload)Play Console → Test and release → App integrity → App signing key certificate

The Play key is the one most often missed: a build works when sideloaded and fails once installed from Play.

Facebook key hashes

Facebook wants the SHA-1 as base64:

echo <SHA1 with colons> | tr -d ':' | xxd -r -p | openssl base64

Local debug key hash: Xo8WBi6jzSxKDVR4drqm84yr9iU=

Meta for Developers → app 3762408017230187 → Settings → Basic → Android:

FieldValue
Package namecom.dryyt.mobile

Until the app is on Google Play, saving shows "There was a problem verifying this package name". Choose Use this package name; the settings save and login works. No rebuild is needed after adding a hash.

Firebase fingerprints

Firebase console → Project settings → Android app com.dryyt.mobile → Add fingerprint: add the SHA-1 and SHA-256 of every signing key. Download a fresh google-services.json afterwards.

Release checklist

Preview

1. worker/: bun run db:migrate:preview 2. worker/: bun run deploy:preview 3. App: bun run gradle:preview (or bunx eas build -p android --profile preview) 4. Install the APK, sign in, place a test order

Production

1. worker/: bun run db:migrate:remote 2. worker/: bun run deploy 3. App: bun run gradle:release (or bunx eas build -p android --profile production) 4. Upload the AAB to Play; check the Play signing key is registered with Facebook and Firebase
