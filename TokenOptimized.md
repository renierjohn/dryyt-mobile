### Optimizing Claude Code: How to Cut Your React Native Token Burn

Building React Native and Expo applications with agentic CLI tools like Claude Code can consume significantly more tokens than traditional web development. This is caused by massive native build logs (Gradle/Xcode), deep file structures, and automatic environment-fixing loops. 

This guide provides configuration templates and best practices to keep Claude Code fast, accurate, and budget-friendly. 

### 1. Implement Strict File Ignoring

By default, Claude Code may scan large, autogenerated native directories or cache files, blowing up your input token baseline. Add a .claudeignore file to the root of your project to block these directories. 

Create a .claudeignore file with the following contents: 

text

# Node modules & package managers
node_modules/
.pnpm-store/

# Expo & Metro caches
.expo/
.metro/
web-build/

# Native build artifacts
android/
ios/
bin/
build/

# IDE and System files
.idea/
.vscode/
.DS_Store
*.log

Use code with caution.

### 2. Scope Tasks with Explicit File Targets

Do not let Claude guess which files to look at. Giving an open-ended prompt forces the agent to read your directory tree and scan files recursively. 

* **Bad Practice:** "Fix the styling on the profile screen button."
* **Good Practice:** "Fix the styling on the profile screen button in @src/screens/ProfileScreen.tsx using the theme variables in @src/theme.ts"

Always use the @ prefix to hard-bind Claude Code's focus to the exact files relevant to your task. 

### 3. Manage Your Session Hygiene

Claude Code remembers previous commands, errors, and files within a terminal session. If you encounter a heavy native build error, Claude will ingest hundreds of lines of Gradle or CocoaPods logs. If you do not clear the session, you will pay for those logs on *every subsequent prompt*. 

* **When to clear:** After fixing a build issue, installing a package, or finishing a specific component.
* **The Command:** Run /clear in the Claude Code prompt to flush the history and reset your context window.

### 4. Control Thinking Effort

For everyday UI modifications, basic TypeScript types, or straightforward state updates, Claude does not need maximum reasoning effort. 

You can toggle the reasoning budget based on your task complexity: 

* **For UI, styles, and basic components:** Set thinking effort to low or medium to slash output tokens.
* **For complex native bridging, deep state bugs, or navigation architecture:** Leave thinking effort on high.

*Tip: Adjust this via your local Claude Code CLI configuration options or environment flags depending on your version wrapper.* 

### 5. Handle Native Dependencies Manually

Letting Claude Code debug a failing native build string or a CocoaPods mismatch can trigger an infinite agentic loop where Claude runs a build, fails, modifies a file, and rebuilds. This can drain your budget in minutes. 

* **The Golden Rule:** Use Claude Code for writing JS/TS React Native code.
* **The Exception:** If a native build fails (pod install errors, Android SDK issues, Gradle mismatches), step in and resolve it manually in your terminal, then run /clear before asking Claude to write code again.

### Quick Reference Checklist

* [ ] Is .claudeignore present in the root directory?
* [ ] Am I using @filename to target specific files?
* [ ] Did I run /clear after the last major terminal error or task switch?
* [ ] Can I lower the thinking effort for this specific UI task?
