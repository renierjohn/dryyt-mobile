Dryyt chat workflow

Customer ↔ driver chat on an accepted job: for meeting up only, so it opens when a driver is assigned and is wiped once the driver has the order or laundry. Messages live in the job room's Durable Object storage, never in D1.

Message flow

Same for every order type; only the room differs (Trip for drop offs, OrderRoom for pickups).

Rules

  • Up to 10 messages each (customer and driver counted separately), 100 characters each, trimmed, not empty (worker/src/lib/chat.ts; the app shows “N of 10 messages left”).
  • Every accepted message is broadcast as the full list ({t:'chat', messages}), so both apps just replace what they show. Reconnecting sends the list again.
  • A refused message gets chat_error back to the sender only; nothing is saved.
  • Outside the window the room ignores chat sends, and the apps hide the chat card.
  • Pickups: a released job clears the chat, so the next driver starts with an empty one.
  • Drop offs: the chat starts empty at Confirm driver (Trip.start); picked up calls Trip.endChat; drop calls Trip.finish; cancel or the end of the trip calls Trip.stop, which deletes the whole room.
  • No push notifications for chat messages; the other side sees them only while the job screen is open.
